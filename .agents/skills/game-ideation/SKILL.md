# Idea to feasible prototype

Inputs: user concept, known platform/dimension/controls/orientation, scope, skill/tool constraints and any research.

1. Resolve only missing essentials using AGENTS.md. Preserve the user's premise and known answers. Identify the experience the player should have, not just a theme.
2. Offer a small set of meaningfully different loops when choice is needed. For each, state the repeated player action, feedback, meaningful decision, failure/recovery and reason to continue.
3. Identify the hardest technical/content dependency, required asset variety and what can be simulated with simple geometry. Score feasibility against the actual platform, time and tools rather than novelty alone.
4. Choose or recommend a direction with reasons. Cut features that do not test the central experience. If the user already chose a clear direction, move directly to refining its slice instead of reopening the choice.
5. Define a short prototype experiment with observable success and stop criteria. Put expensive systems behind a later decision gate.

Validation: another person can describe what they do in the first minute; constraints are recorded; no unrequested services or implementation claims appear.

Output: concept, constraints, tradeoffs, scope exclusions, highest-risk experiment and the next design task. Record any selected direction in project state.

Shared setup: [AGENTS.md](../../../AGENTS.md). Record results with [project state](../../../docs/project-state.md).
