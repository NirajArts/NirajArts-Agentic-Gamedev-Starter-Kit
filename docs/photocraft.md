# PhotoCraft 0.17.0: local art workflow

Use the [official Windows x64 portable ZIP](https://github.com/storytold/photocraft/releases/download/v0.17.0/photocraft-0.17.0-windows-x64-portable.zip). The [version-pinned packaging source](https://github.com/storytold/photocraft/blob/v0.17.0/packaging/windows/package.ps1) places both executables in `photocraft-0.17.0-windows-x64-portable/`. Move that wrapper's **contents**, including `portable.txt` and all notices, into `tools/photocraft/`. Do not flatten individual resource directories or keep only the executables. The starter intentionally includes no downloaded binaries.

Expected paths: `tools/photocraft/photocraft.exe` and `tools/photocraft/photocraft-cli.exe`. The release metadata inspected on 2026-11-02 reports 126,317,468 bytes and SHA256 `3453777af0a0b376bfea0d1ccf42bedcbe1c324e1836b50d6227b9e1d64a20ab` for the downloaded ZIP. Verify your download against the release's current metadata before extraction. The package structure was checked from pinned source, not by executing the app.

Portable mode can create `PhotoCraftData/` beside the executables for settings and recovery. Keep this runtime directory out of Git and shared packages too; it may contain private working data.

## Launch

From the repo root:

```powershell
pwsh -File scripts/Start-PhotoCraft.ps1 -CheckOnly
# First launch: explicitly authorize PhotoCraft to create the local credential.
pwsh -File scripts/Start-PhotoCraft.ps1 -AllowTokenCreation
# Later launches reuse the same file.
pwsh -File scripts/Start-PhotoCraft.ps1
```

The launcher derives the repo root from its own file, verifies both binaries and port availability, rejects linked runtime/tool paths, and prepares `.local/` with user-only Windows access before launch. It refuses an existing `.local/` directory whose ACL grants another principal access; fix that deliberately rather than changing unrelated files' permissions. It refuses linked credentials and checks an existing token's ACL as well. No token is generated by this script; PhotoCraft creates/reuses `.local/photocraft-control.token`. No credential is printed. `-CheckOnly` does not create directories, credentials or processes. It does not prove the binary is valid.

Equivalent flags, shown for understanding (the launcher handles quoting and paths):

```text
photocraft.exe --control 9880 --control-token-file <absolute-repo>/.local/photocraft-control.token --automation-read-root <absolute-repo> --automation-write-root <absolute-repo>
```

The desktop's [pinned control protocol](https://github.com/storytold/photocraft/blob/v0.17.0/docs/control-protocol.md) documents loopback binding, token-file creation/reuse and these root flags. The script passes argument values separately and clears inherited PhotoCraft control/root environment overrides in the child. It does not disable authentication or redirect credential output into a shared log. A successful process start is only a launch attempt: inspect the app and authenticated connection before declaring it ready. Repository read/write roots cover this workspace; agents must still keep edits within the selected game's assets and leave other games untouched.

If port 9880 is occupied, the helper stops. Identify whether it is the intended PhotoCraft instance; do not kill it or assume its roots match. An existing GUI launched without control needs a deliberate save-and-restart with these flags. Obtain consent first if it contains unsaved work. Do not change ports in one side of a connection only. An occupied port is not proof that authentication will work.

## Agent connection

After a successful launch, use a bridge for the same GUI session:

```powershell
$repoRoot = (Resolve-Path .).Path  # run from the repo root
& (Join-Path $repoRoot 'tools/photocraft/photocraft-cli.exe') mcp --bridge 127.0.0.1:9880 --control-token-file (Join-Path $repoRoot '.local/photocraft-control.token')
```

Configure this as a stdio MCP server in the agent client only if requested, using the client's current documentation. [Bridge mode](https://github.com/storytold/photocraft/blob/v0.17.0/book/src/automation/mcp.md) consumes the same token file; **do not put desktop automation-root flags on the bridge command**. Do not paste the credential into client config. For a simple authenticated inspection without MCP, run `python scripts/photocraft_inspect.py`; it reads the file privately, authenticates once and prints only a redacted inspection result. It is a read-only client, not an editing API. Keep tool outputs local because document metadata can include private filenames.

For editing, discover the connected tool schema, select the intended document and preserve source layers. Use capability-scoped document open/save operations from the installed protocol. Do not guess an engine command's parameters or substitute unrestricted file commands. Inspect actual exported images and Unity imports. If a command times out, inspect document/job state before retrying; an uncertain result may already have changed the document.

## Credentials and sharing

The repo-local token is intentional so the local coding agent can read it. `.gitignore` excludes `.local/`, but ignores do not prevent folder uploads, backups or synchronization. Never share your working directory wholesale. Use the clean starter packager for the template; use a reviewed allowlist for any game archive. Neither packager should include tokens. If a credential leaks, save work, stop the authorized instance, remove/rotate the token with consent and restart; never publish the old value.

Windows ACL checks assume a filesystem supporting ACLs (normally NTFS). If protection fails, launch stops; use a suitable private location rather than weakening access. The provided launcher is Windows-only. On another OS, use the official release for that OS and its current instructions with a private token file and matching workspace roots.
